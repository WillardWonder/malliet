How the planner works
1. Assign farms to load slotsRegret-based insertion tests every practical driver, load, and position against capacity, windows, shifts, risk, cost, and balance.
2. Improve stop orderRepeated relocations, swaps, run changes, and 2-opt reversals search beyond nearest-neighbor routing.
3. Schedule real workRoad travel, waiting, loading, return travel, unloading, availability, and maximum shift length are simulated.
4. Delay starts intelligentlyCritical candidate departure times are tested so drivers do not begin before they need to.
5. Balance people and costThe score considers total cost, fleet miles, waiting, route overlap, high-count risk, and driver-hour spread.
6. No false optimality claimThe method is a multi-start heuristic. It verifies the selected constraints but cannot prove a global optimum.

Method, guarantees, and deployment limits

What the browser tool is doing, what it verifies, and what still requires human judgment.

Planning method

Farm assignment
Multiple seeded regret-insertion starts evaluate every practical insertion into every available driver load. Expected capacity is hard; high-count capacity is either a warning or hard constraint depending on settings.
Stop order
Relocate, swap, cross-run, and 2-opt improvement passes repeatedly test different sequences using the same time and capacity simulator.
Windows and service
Arrival, early waiting, service start, loading duration, return travel, unloading duration, driver availability, and shift limits are included.
Driver starts
The tool tests critical start times generated from farm windows and cumulative route work, then chooses the feasible start with the best score.
Workload balance
Driver duty-time range and variance are penalized alongside miles, cost, waiting, and overlap. Objective settings change the relative weight.

What it can and cannot guarantee

It verifies the plan it displays against the entered expected counts, pickup windows, loading times, availability, maximum shifts, and trailer capacity.
It cannot verify bad inputs. A wrong pin, count, duration, closure, restriction, or farm instruction can make a valid-looking plan unusable.
It does not prove a global optimum. The result is the best plan found by a browser-friendly heuristic.
Firebase is the shared operational record. Authentication, company directories, dispatch days, released route versions, and driver progress synchronize through Cloud Firestore. The browser keeps a local cache for offline continuity.
Concurrent edits are protected, not magically merged. If two dispatchers change the same day from different devices, the system stops a stale save and asks whether to reload or deliberately overwrite.

Map and routing services

The page uses OpenStreetMap tiles, a configurable OpenStreetMap-based geocoder, and a configurable OSRM-compatible routing endpoint. Public community services are suitable only for light evaluation use and can be unavailable or rate-limited.

For permanent fleet deployment, use a hosted or self-hosted tile, geocoding, and routing service with an agreement appropriate for operational traffic. The service endpoints can be changed under Data & settings.

Human release rule

Never release a route solely because the screen says feasible. Dispatch must confirm the current calf counts, farm access, vehicle readiness, employee availability, road conditions, and any legal or animal-handling requirements.
